# CTRL+ALT+DATA

**Your pipeline ran green last night. Are the numbers right?**

If you hesitated, this repo is for you.

I'm Kushagra Soni, a Solutions Architect. I design data and AI platforms for banks, which mostly teaches you what breaks, when it breaks, and who gets the phone call. CTRL+ALT+DATA is my 14-part series across three tracks on Medium about the job behind the dashboards. The articles explain the ideas. This repo is where you get your hands dirty. Each part comes with a small exercise you run on a laptop, break on purpose, and fix. Parts 1 and 2 are ready now and each takes under half an hour.

Everything here runs offline with Python and three packages.

## Scenarios you'll recognise

*Made up, but only just.*

- **Part 1 (Silent drops):** On Friday, the team that sends you a daily payments file ships a small tidy-up: dates go from `2026-03-06` to `06/03/2026`. Nobody tells you. Monday, 07:40, your job runs. Green tick. At 08:00 the dashboard shows 40% fewer transactions because the parser turned the new dates into nulls and `clean()` dropped them.
- **Part 2 (Midnight cutoffs, duplicate retries & destructive ETL):** A customer swipes a card at `23:54 UTC` on Sunday, but a mobile offline queue delivers the event at `00:12 UTC` Monday. Naive arrival-time batching books Sunday's revenue into Monday's ledger, gateway ACK timeouts double-count 30 retries, and an ETL transform that overwrites raw payloads makes a currency-conversion bug impossible to replay without re-requesting feeds from the gateway.

## Quickstart

You need Python 3.10 or newer. On macOS and Linux:

```bash
git clone https://github.com/ctrl-alt-delta/ctrl-alt-data.git
cd ctrl-alt-data
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python part1/run.py
python part2/run.py
```

On Windows (PowerShell), the same thing with Windows paths:

```powershell
git clone https://github.com/ctrl-alt-delta/ctrl-alt-data.git
cd ctrl-alt-data
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python part1/run.py
python part2/run.py
```

(In `cmd.exe`, activate with `.venv\Scripts\activate.bat` instead.)

**About the data:** the transactions are generated by `part1/data/generate.py` and `part2/data/generate.py` from fixed seeds, so everyone gets the exact same files. The accounts, amounts, merchants, and partners are made up. There are no real customers and no company data anywhere in this repo.

Run the test suite across both parts:

```bash
python -m pytest part1 part2 -v
```

**Prefer uv?** Swap the venv and pip lines for these, then activate `.venv` as above:

```bash
uv venv
uv pip install -r requirements.txt
```

## Part 1 in four steps

The full instructions are in [part1/README.md](part1/README.md).

1. **Warm-up (10 min, optional):** run the finished pipeline, hunt for the mess in the CSV, and answer the five questions in `pipeline_card.yaml`.
2. **Main exercise (10 min):** finish `clean()` and `load()` in `part1/starter/pipeline.py`.
3. **Break it (5 min):** `python part1/run.py --target starter --break date-format`, and watch it load the wrong numbers without complaint.
4. **Fix it (10 min):** write the row count and freshness checks, replay the incident, and watch it stop.

## Part 2 walkthrough: Batches, Streams & Screams

The full instructions are in [part2/README.md](part2/README.md).

1. **Event-time watermarks & idempotent dedup:** `python part2/run.py --fresh` lands 600 raw payment events into `bronze_payments`, routes 15 malformed poison pills to `dlq_quarantine`, drops 30 gateway retry duplicates by `txn_id`, and books 45 late-arriving pre-midnight swipes into their true `2026-10-25` settlement date (`300` rows on `2026-10-25`, `255` on `2026-10-26`).
2. **Destructive ETL vs replayable ELT:** run `python part2/run.py --mode etl-bug` to see why transforming before load loses raw amounts when an FX/interchange bug hits, then run `python part2/run.py --mode elt-replay` to replay clean SQL transforms from `bronze_payments` in milliseconds.
3. **Break it on purpose:** test `--break arrival-time-cut`, `--break duplicate-retry`, `--break etl-fx-bug`, `--break watermark-stall`, `--break poison-pill`, and `--break silent-drop`—each fails loudly at the check gate while preserving the last good warehouse table.

## Starter vs solution

Every part has the same two folders:

- **`starter/`** is yours. It has the boring parts done and clear `TODO`s where the thinking goes.
- **`solution/`** is my version. It passes every test.

Commands default to the solution. Add `--target starter` to run or test your own code:

```bash
python part2/run.py --target starter                # list remaining TODOs (exits code 2)
python part2/run.py --check --target starter        # test your starter implementation
python -m pytest part1 part2 -v                     # run all solution tests across Part 1 & Part 2
```
